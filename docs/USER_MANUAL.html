第一章：系统概述

1.1 系统简介

报销稽核系统是面向基层单位的离线优先桌面应用，用于管理"差旅报销"的全流程。三种角色使用不同的客户端，共享一套 SQLite 数据库：

1.2 三种角色对比（v2.10.0d 角色职责明确）

角色性质客户端核心职责关键功能
财务 岗位账户 财务版 创建稽核员、终审、配置 终审、双签、override、报表、审计、导入导出、字典、大屏、升级、下发稽核员客户端
稽核员 岗位账户 稽核员版 创建报销员、创建项目、初审、考勤审批 初审、查重、代填报销 + 代填考勤（直接通过）、审批报销员考勤、创建项目+项目人员、下发报销员客户端、管理代理关系
报销人 自然人 报销人版 自助录考勤、自助报销 录入单据、查看进度、上传附件、OCR 识别、录入考勤（待稽核员审核）
ℹ v2.10.0d 职责边界：
  • 财务：唯一能创建稽核员、唯一能下稽核员客户端
  • 稽核员：能创建报销员、能创建项目、能下报销员客户端、能代填、能审批
  • 报销员：自助录待审考勤 + 自助待审报销，无任何代理管理权（不能设/撤代理）
⚠ 角色与客户端严格绑定：报销人账号登录财务客户端会被拒绝（O12 决策）。

4.5 代理关系管理（v2.10.0d 核心）

代理关系决定一个报销员是否需要登录客户端，还是由稽核员全权代办。代理关系由 财务/稽核员在"项目台账"中为该项目设置（按项目粒度），报销员无权设置。

[项目台账] → 选项目 → [🤝 代填] 按钮
                ↓
        ┌──────────────────────┐
        │ 选稽核员:  [audit001] │
        │ 选报销员:  [reimb001] │
        │ 代理模式:  [全权]     │  ← full / attendance_only / bill_only
        │ 有效期:    [2026-08-25 → 2026-12-31] │
        └──────────────────────┘
                ↓
        [建立] → agent_auth 记录入库
                ↓
        报销员 mode-c-status 自动更新

代理模式 C 三种状态（基于项目覆盖度）

状态判定是否生成客户端
agent_c 报销员所有项目都被代理 ❌ 不生成（稽核员全权代办）
partial 部分项目被代理 ✅ 生成（混合模式）
self 无代理关系 ✅ 生成（自助模式）
orphan 未绑定任何项目 ⚠ 暂不生成

代理权限分级（v2.10.0d 新增）

agent_mode代填考勤代填报销
full✅ 直接通过✅ 直接通过
attendance_only✅ 直接通过❌ 无权
bill_only❌ 无权✅ 直接通过
⚠ 报销员无任何代理管理权：
  • 报销员不能设置代理（API 拦截：403）
  • 报销员不能撤销代理（API 拦截：403）
  • 报销员看不到"代理关系"菜单
原因：报销依托项目，项目由稽核员/财务创建，所以代理由创建方设置。

8.2 OCR 全离线（v2.9.0）

报销票据 OCR 引擎从"模拟引擎"升级为 rapidocr_onnxruntime，PaddleOCR v4 中文模型， 完全本地推理，不依赖任何外网 OCR API。

ℹ v2.9 OCR 引擎升级：
  • 引擎：rapidocr_onnxruntime（替代 v2.7 的 mock）
  • 模型：ch_PP-OCRv4_det + ch_PP-OCRv4_rec
  • 性能：~1.6s/图，置信度 0.95+
  • 降级：rapidocr 不可用时自动 fallback 到 mock（保证测试不挂）
  • 部署：模型文件内置在 python/Lib/site-packages/rapidocr_onnxruntime/models/

8.4 模式 C 混合部署（v2.10.0c / v2.10.0d）

模式 C = 部分报销员由稽核员全权代办，其他报销员自助登录。 核心机制：复用 agent_auth 表（不引入新字段），有 active 关系 = 模式 C。

模式 C 端到端工作流

  1. 财务创建项目（自动绑报销员到 user_project）
  2. 财务/稽核员进"项目台账" → 选项目 → [🤝 代填] 按钮
  3. 选稽核员 + 选报销员 → 建立 agent_auth
  4. 报销员 mode-c-status 自动从 self 变 agent_c
  5. 客户端分发自动跳过该报销员（提示"完全模式 C"）
  6. 稽核员端"考勤"视图能选代填对象
  7. 报销员状态变化通知自动抄送稽核员（标题前缀"代 [姓名]"）

Q3：大额报销（≥ 10 万）我登录了为什么看不到"双签"菜单？

A：双签只对第二签人显示。你是主财务，应该用"主财务 approve"流程：

  1. 终审工作台 → 选大额单据 → 终审通过
  2. 系统会要求你选第二签人
  3. 选完后单据进入"待双签"状态，由第二签人在他自己的客户端审批

Q4：OCR 票据识别返回的是空字段？

A：当前使用模拟 OCR 引擎。要真实识别：

  1. 部署时配置 BAIDU_OCR_TOKEN（百度 OCR API 密钥）
  2. 或部署 Tesseract + 中文模型
  3. 启用 services/ocr_service.py 中的 baidu_ocr 函数

Q5：升级失败怎么办？

  1. 系统会自动备份到 backups/pre_upgrade_{version}_{ts}.db
  2. 升级失败时显示错误日志
  3. 手动恢复：停服务 → 备份文件覆盖 reimbursement.db → 启动

Q6：客户端连不上中心节点？

  1. 检查中心节点（财务客户端）是否启动
  2. 检查防火墙是否放行 5443 端口
  3. 检查 sys_config.center_node_host 配置

Q7：附件上传失败？

  • 单个文件最大 50MB
  • 格式：jpg / png / pdf / bmp / gif
  • 检查 uploads/ 目录权限

Q8：为什么我的角色登录到了不同的客户端被拒绝？

A：O12 决策 — 客户端类型与角色严格绑定：

  • admin / finance_* → 财务客户端
  • audit_* → 稽核员客户端
  • reimb_* → 报销人客户端

如需切换角色，请联系财务管理员调整。

Q9：日志在哪里看？

  • 桌面应用日志：logs/ 目录
  • 启动日志：每次启动时 logs/launch_{ts}.log
  • 错误日志：菜单 📜 审计日志 或 error_log 表

Q10：怎么备份数据？

  • 手动备份：复制 reimbursement.db 文件
  • 自动备份：升级向导会备份
  • 定时备份：可用 crontab： 
    0 2 * * * cp /path/to/reimbursement.db /backup/reimburse_$(date +\%Y\%m\%d).db
