# 第一章：系统概述

## 1.1 系统简介

报销稽核系统是面向**基层单位**的离线优先桌面应用，用于管理"差旅报销"的全流程。三种角色使用**不同的客户端**，共享一套 SQLite 数据库：

```
┌─────────────────────────────────────────────────────┐
│                 同一台电脑 / 局域网                     │
│                                                     │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐         │
│  │ 报销人版  │   │ 稽核员版  │   │  财务版   │         │
│  │ (发起)   │   │ (初审)   │   │ (终审)   │         │
│  └────┬─────┘   └────┬─────┘   └────┬─────┘         │
│       │              │              │              │
│       └──────────────┴──────────────┘              │
│                  │                                  │
│                  ▼                                  │
│            ┌──────────┐                            │
│            │reimburse │                            │
│            │  .db     │  SQLite                    │
│            └──────────┘                            │
└─────────────────────────────────────────────────────┘
```

## 1.2 三种角色对比

| 角色 | 客户端 | 核心任务 | 关键功能 |
|------|--------|----------|----------|
| **报销人** | 报销人版 | 发起报销 | 录入单据、查看进度、上传附件 |
| **稽核员** | 稽核员版 | 初审 | 审核金额、查重、代填 |
| **财务** | 财务版 | 终审/管理 | 终审、双签、override、报表、审计 |

> ⚠ **角色与客户端严格绑定**：报销人账号登录财务客户端会被拒绝。

## 1.3 单据生命周期

```
   草稿        提交          初审通过        终审
(draft) ─→ 提交 ─→ (submitted_auditor) ─→ (auditor_ok) ─→ (submitted_finance)
              │              │                  │
              │              │                  ├─ 小额 ─→ (approved) ─→ (archived)
              │              │                  └─ 大额 ─→ (pending_dual_sign)
              │              │                                  │
              │              │                                  ▼
              │              │                            第二签人批准
              │              │                                  │
              │              │                                  ▼
              │              │                            (approved) ─→ (archived)
              │              │
              │              └→ (rejected_auditor) ─→ 退回报销人修改
              │
              └→ (rejected_auditor) ─→ 退回报销人
```

# 第二章：启动与登录

## 2.1 启动客户端

### Windows

```
桌面双击 → reimbursement_finance.exe
   ↓
首次启动：弹出"依赖检查"窗口
   ├─ ✓ 依赖完整 ─→ 直接进入登录
   └─ ✗ 缺依赖 ─→ 显示缺少的包名
       ↓
       自动下载安装（联网时）
       或手动执行 install_deps.sh
```

### Linux (麒麟/UOS/Deepin)

```bash
# 终端
cd ~/reimbursement_finance
./launcher_finance.sh
# 或直接双击 "reimbursement_finance" 可执行文件
```

### macOS（开发用）

```bash
cd /path/to/reimbursement_finance
./launcher_finance
```

### 默认账号

|------|--------|----------|
| 财务（管理员） | `admin` | `NewP@ss123` |
| 稽核员 | `audit001` | `Audit@001!` |
| 报销人 | `reimb001` | `Reimb@001!` |

> ⚠ **首次登录强制改密**。新密码至少 10 位，必须含大小写字母 + 数字。

## 2.3 登录失败处理

| 情况 | 现象 | 处理 |
|------|------|------|
| 密码错误 | "用户名或密码错误" | 重试 5 次会锁定账号 30 分钟 |
| 账号锁定 | "账号已锁定" | 等待 30 分钟自动解锁，或联系管理员 |
| 客户端类型不匹配 | "无权访问此客户端" | 检查你打开的是不是正确的客户端 |
| 网络问题（中心节点） | "无法连接中心节点" | 检查中心节点服务是否启动 |

## 3.5 处理被驳回的单据

1. 进入 **📋 我的报销单**
2. 找到状态为 `rejected_auditor` / `rejected_finance` 的单据
3. 点击查看驳回原因（稽核员/财务的批注）
4. 点击 **修改** 按钮（或新建并复制）
5. 修改后重新提交

## 4.2 初审单据（核心工作）

### 步骤 1：进入待审单据

点击 **⏰ 待审单据** 菜单。显示所有状态为 `submitted_auditor` 的单据。

### 步骤 2：审核单据

点击 **通过** 或 **驳回** 按钮：

**通过** 流程：
```
点击 [通过]
   ↓
输入审核意见（可选）：
"金额合理，同意报销"
   ↓
点击 [确认]
   ↓
单据状态: submitted_auditor → submitted_finance
（流向财务终审）
```

**驳回** 流程：
```
点击 [驳回]
   ↓
必填驳回原因（≥10 字符）：
"交通费超标，建议改用公交"
   ↓
点击 [确认]
   ↓
单据状态: submitted_auditor → rejected_auditor
（退回报销人修改）
```

> 💡 驳回原因会作为通知发给报销人，并自动填入单据的批注栏。

### 步骤 3：金额校验

系统自动校验（也支持稽核员手动调整）：
- 伙食补助：按出差天数 × 标准自动计算
- 住宿标准：按职务等级 + 城市类型查找
- 重复检测：同一项目同一人 30 天内是否有同类报销

## 4.3 代填报销 ✍️

> ⚠ 代填的单据 = G2 决策：跳过稽核员初审，直接进入财务终审。

### 5.2.4 大额双签（≥ 10 万元）

```
点击 [✓ 终审通过]
   ↓
系统提示：大额报销需双签，请指定第二签人
   ↓
从下拉框选择第二签人（必须不是自己）
   ├─ 张三（财务）
   ├─ 李四（财务）
   └─ ...
   ↓
输入终审意见 + 确认
   ↓
单据状态: submitted_finance → pending_dual_sign
   ↓
通知发给第二签人
   ↓
第二签人登录 → 菜单 "🤝 待双签" → 同意/拒绝
   ↓
通过：pending_dual_sign → approved → archived
拒绝：pending_dual_sign → rejected_finance
```

> ⚠ 第二签人**必须实际登录**才能批准，不能代办。

# 第七章：常见问题 FAQ

## Q1：忘记密码怎么办？

**A**：联系财务管理员重置密码。财务进入 **👥 人员账号** → 找到该用户 → **改密**。

## Q2：单据被驳回后，找不到修改入口？

**A**：进入 **📋 我的报销单** → 点击"财务驳回"或"稽核驳回"状态的行 → 详情页有 **修改** 按钮（或新建并复制内容）。

## Q3：大额报销（≥ 10 万）我登录了为什么看不到"双签"菜单？

**A**：双签只对**第二签人**显示。你是主财务，应该用"主财务 approve"流程：
1. 终审工作台 → 选大额单据 → 终审通过
2. 系统会要求你选第二签人
3. 选完后单据进入"待双签"状态，由第二签人在他自己的客户端审批

## Q4：OCR 票据识别返回的是空字段？

**A**：当前使用**模拟 OCR 引擎**。要真实识别：
1. 部署时配置 `BAIDU_OCR_TOKEN`（百度 OCR API 密钥）
2. 或部署 Tesseract + 中文模型
3. 启用 `services/ocr_service.py` 中的 `baidu_ocr` 函数

## Q5：升级失败怎么办？

**A**：
1. 系统会自动备份到 `backups/pre_upgrade_{version}_{ts}.db`
2. 升级失败时显示错误日志
3. 手动恢复：停服务 → 备份文件覆盖 `reimbursement.db` → 启动

## Q6：客户端连不上中心节点？

**A**：
1. 检查中心节点（财务客户端）是否启动
2. 检查防火墙是否放行 5443 端口
3. 检查 `sys_config.center_node_host` 配置

## Q7：附件上传失败？

**A**：
- 单个文件最大 50MB
- 格式：jpg / png / pdf / bmp / gif
- 检查 `uploads/` 目录权限

## Q8：如何导出指定时间范围的报销单？

**A**：进入 **📈 统计报表** → 选日期范围 → **单据明细导出** → Excel/PDF。

## Q9：为什么我的角色登录到了不同的客户端被拒绝？

**A**：**O12 决策** — 客户端类型与角色严格绑定：
- `admin` / `finance_*` → 财务客户端
- `audit_*` → 稽核员客户端
- `reimb_*` → 报销人客户端

如需切换角色，请联系财务管理员调整。

## Q10：如何重置数据库（清空所有数据）？

**A**（**警告**：所有数据会丢失！）：
```bash
# 1. 停止所有客户端
# 2. 删除数据库文件
rm reimbursement.db

# 3. 重新启动（会触发初始化 + 预置 admin 账号）
python3 migrate.py upgrade
```

## Q11：并发问题？两个财务同时终审同一单据？

**A**：SQLite 串行写 + 状态机校验。如果两人同时操作：
- 先到的人成功（状态变更）
- 后到的人收到"状态已变更"错误
- 刷新页面查看最新状态

## Q12：日志在哪里看？

**A**：
- 桌面应用日志：`logs/` 目录
- 启动日志：每次启动时 `logs/launch_{ts}.log`
- 错误日志：菜单 **📜 审计日志** 或 `error_log` 表

## Q13：如何备份数据？

**A**：
- **手动备份**：复制 `reimbursement.db` 文件
- **自动备份**：升级向导会备份
- **定时备份**：可用 `crontab`：
  ```bash
  # 每天凌晨 2 点备份
  0 2 * * * cp /path/to/reimbursement.db /backup/reimburse_$(date +\%Y\%m\%d).db
  ```

## Q14：沙箱无法装 flask-limiter？

**A**：项目已**手写限速**（`utils/ratelimit.py`），不需要 flask-limiter。生产环境如需更精细限速可装。

## Q15：怎么升级到最新版本？

**A**：在 **财务版**菜单 **🚀 应用升级** → **检查更新** → **升级前预检** → **一键升级**。
